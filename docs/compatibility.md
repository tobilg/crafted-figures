# Compatibility contract

The 0.7.0 built artifact uses only our Three.js-based implementation for solid authoring and ships its authoring runtime. Node 22.13+ or Node 24+ is required; no npm installation is needed for standalone commands. Vite 8.3.5 replaces esbuild and embeds Rolldown 1.2.15 with its portable WASI binding, Ajv 8.20.0, Playwright Core 1.64.1 and Three.js 0.186.1. Install the built ZIP; source-only GitHub folder installation now requires a repository build. Runtime bundles, generated types and recipe copies are intentionally ignored in Git. See [artifact packaging](artifact-packaging.md) for this increment and [removal evidence](legacy-removal.md) for 0.5.0 and [bundled-runtime evidence](bundled-runtime.md) for the earlier Vite increment. The full replacement qualification below remains historical 0.3.1 evidence, not a new full release claim. Tested integration versions are React/React DOM 19.3.1, Next 16.4.2, TypeScript 7.0.2, @types/react 19.3.0 and @types/three 0.186.0. These are tested versions, not evidence for every version admitted by an optional peer range. Chromium 156.0.8078.4 on Darwin x64 has executed browser evidence. Linux CI is configured but has not run remotely; other browsers, hardware GPUs and OSes remain untested.

**Platforms.** Linux, macOS and Windows run the no-install consumer on hosted CI at Node 22.13.0 and 24, and builds and source bundling passed on all three in [run 41189536149](https://github.com/tobilg/crafted-figures/actions/runs/41189536149). The first hosted run failed on every Windows build; 0.7.0 fixed that by moving module loading out of the WASM file system. Browser checks and printing run on hosted Linux and locally on macOS, not on Windows.

**Behaviour changes in 0.7.0.** HTML figures and print pages no longer carry a product name (set `eyebrow` to add a label). SVG IDs and styles are scoped to the figure, so `figure-title` becomes `<figure>-<hash>-title`. Audits check every solid pair even when a scenario lists clearances (`clearanceScope: "declared"` restores the old focus) and an empty list no longer removes a declared check (use `replaceDeclared`). `setState` on a scalar scene rejects a key it cannot honor. A figure built with schema 1 that calls `material()` builds with a warning. Tools read `controller.stage` and `controller.effects`; `root.__stage` and `root.__effects` remain as aliases. The figure, model and configuration contracts are otherwise unchanged, and the frozen regression sources still build unmodified.

Schema 1 preserves the existing fixed authored camera and fields. Explicitly select schema 2 for camera views, detailed mode, semantic material overrides and effect policy. Numerical camera validity does not imply that a figure supports the view. JSON preset and material schemas are separately versioned and reject unknown fields. Configuration upgrades do not rewrite sources or change a model.

`render({kit,config,tokens,state})` and mount cleanup functions remain supported. Advanced mounts may return an instance controller; browser kit/tokens arguments are additive. A selected exported pose initializes both static art and client state. Version 0.5.0 intentionally removes the retained prototype projection/solid helpers and their generated types, following the owner’s explicit instruction. No shim remains. Existing sources that used those helpers must map to `kit.illustration` as described in the [capability mapping](legacy-removal.md); schema-1 configuration itself needs no migration. All current examples already used our Three.js implementation.

This is not source/API drop-in compatibility with Anatomy. Map its projection to an orthographic Three stage, moving groups to native transforms, primitives to illustrated helpers, and state to pure model functions. Map style ramps to presets/material roles, masks to matching depth or a qualified layer split, and React/print wrappers to the adapters/sheet contract. Bespoke shader code needs manual adaptation; arbitrary shader conversion, general meshes and free perspective orbit are unsupported. Sources remain untouched by builds.

The independent R09 author migrated the original basic dial and articulated combination dial. Its completed continuation (local evidence: `out/reports/replacement-evals/R09-corrected/evaluation.md`) restores wiring, surface details, original numeric/control relationships, LED and seeded world-space particles. It verifies 43 rendered poses, 1,441 dial/221 time samples, 70 particle snapshots, original world transforms, native controls, both themes and two independent eight-artifact hash comparisons. A real 300° painter cycle required decomposition of the actual joint cap; its exact failed unsplit geometry is retained. This is evidence of a supported manual migration, not automatic conversion.

The frozen trial's articulated generic export timed out twice at 30 seconds. Concurrent-load pose samples took 6.0–7.4 seconds; they are not idle capacity figures. The original custom green/orange shaders, directional receiver lighting, projection convention and some fine bevel/finish details differ. Flying spark trails are absent from that trial's vector fallback, which retains the mechanics, light core and explicit count. The current-toolkit maintainer follow-up (local evidence: `out/reports/source-migration-current/report.json`) passes all eight generic checks on each unchanged author source plus three articulated moving-order poses, including 300°. Measured synchronous pose updates on 0.3.1 remain 3.6–4.4 seconds for 654 solids on this machine. That follow-up does not retroactively turn the frozen failures into passes. See [readiness](replacement-readiness.md) for the resulting gate decision.

Codex is the observed agent host. R08 used actual codex-cli 0.163.0 discovery/execution with a relevant isometric request and an unrelated Mermaid request. Other Agent Skills hosts are compatible-format only until tried. The skill owns its dependencies; generated standalone files need neither npm nor network access. The compatibility suite (local evidence: `out/reports/compat/report.json`) executes v1/v2 tests, strict types, isolated standalone and real Next consumers, and separate basic/hybrid-print source-bundle rebuilds. Global installation and publication remain separate user actions. The reference is clean at `1482e8469b0a9e0d8cc18ea2740a01423d29ae80`.
