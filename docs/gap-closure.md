## Corrections discovered during verification

- The first independent profile probe differed exactly at an adjacent analytic band boundary. The checker reports exclusions only at a shared ring between adjacent chunks of the same analytic profile and within its declared meridian approximation tolerance. The recorded sample lies about 0.000077 viewBox units from that ring; unrelated solids and interior swaps remain failures. The initial failure is preserved in `out/reports/gap-closure/initial-order-failure.json`. This is a documented finite approximation boundary, not universal silhouette correctness.
- A separate vent-edge mismatch exposed the checker's CSS-bounds/viewBox mapping error. It now uses the actual SVG screen transformation, accounting for browser layout rounding and aspect-ratio alignment. No vent geometry or painter bias was changed to mask the mismatch.
- The first static-print regression fixture used a `file:` import that esbuild does not resolve. The fixture now imports by a relative module path. This was a test harness issue; static pose rendering then executed.
- Visual inspection caught an overlong construction readout. It now states only the model-driven assembly angle; explanatory text stays in the surrounding description/legend. A real SVG bounding-box assertion guards this regression.
- The wider motion audit found a new spark glyph intersecting the emitting tool at birth. The vector glyph now grows within measured clearance from the tool/lamp envelope; the lamp core represents emission before a separate glyph fits. Its model position, GPU depth pass and explanatory motion are unchanged. Exact births and nearby times are regression-tested. The independent frozen verification trial also found a lamp/spark overlap at 2.31 seconds; its original failure remains preserved and is not rewritten as a fresh-agent success.
- A sandboxed unit run failed to bind its preview server to loopback. The authorized local-server rerun is the release evidence; the initial denied run is not counted as a product pass.
- `release-attempt-1/` retains a deliberately invalidated receipt: inputs changed while fidelity checks were running. The new aggregator correctly refused that execution as evidence for the later delivery. Current receipts require unchanged inputs throughout each execution.

## Scope and reproducibility

Run `npm run types:build`, `npm run package:skill`, then `npm run test:release` and `npm run test:parity`. The full local release requires the archived source-migration/evaluation inputs; it does not invent or download fresh agent evidence. Individual release steps can be rerun, for example `node tests/release.mjs audit gaps compat`. A receipt is reusable only if its package, runtime and verification inputs still match. Independent report contents and command logs are hashed; empty or undersized reports fail even when their top-level status says `passed`. Changing source or test inputs invalidates affected delivery evidence conservatively.

The [construction example](../examples/construction-details/figure.mjs) is shipped as an independent template. Both preset/theme combinations and three declared cameras are exercised at 390/960 CSS pixels and three model poses. Tests and research remain outside the installable skill. Three.js still owns the scene/geometry/camera; the illustration adapter remains responsible for SVG style/order. The historical experiment remains excluded.

The 33 ms budget remains deferred. Finite sampling, tessellation and qualified camera/geometry limits remain explicit. Native flat faces and analytic profiles receive independent tone checks; swept-route shading is supported by route geometry/facing fixtures and visual inspection, not an analytic general-surface proof. No hardware-GPU, alternate browser/OS or remote-CI qualification is claimed. Existing R01–R10 frozen agent trials retain their original package hashes and outcomes; focused follow-ups are separately identified.
