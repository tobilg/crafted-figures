# Provenance

Reference: https://github.com/wheresryan22/anatomy.git at `1482e8469b0a9e0d8cc18ea2740a01423d29ae80`; parent gitlink records this exact analyzed baseline. No baseline difference. Reference files are unmodified. Builds do not import from reference/.

In 0.5.0, the owner authorized removing the retained prototype implementation. The stable source, types and assembled package now contain only our Three.js-based illustration implementation. The former helper module and its string-rendering wrappers are deleted, not hidden behind aliases. The following table records historical provenance; it is not a list of current runtime imports. [Capability mapping and evidence](legacy-removal.md) documents the transition. New build manifests identify Anatomy as a design reference only. Historical packages, fixtures and evaluation sources retain their original notices.

Read for design comparison: SKILL.md, agents/openai.yaml, scripts/inline-kit.mjs, references/craft.md, references/motion.md and references/kit.md. Upstream product mandates are not inherited. No publishing or session scripts are included. New code licensing is left to the owner.

For verification, reviewed references/verify.md, scripts/capture.mjs, scripts/drive.mjs and the projection audit. Our tests are independently authored for the smaller contract. For P4, reviewed kit/gl.mjs, references/webgl.md, ripple-tank build/live layering, raptor-engine live occlusion, and turning-dial live/turn masking assumptions. These supplied design context; none of the raw WebGL bridge, shader examples, turn engine, scene masks, gallery or session scripts was copied.

The independent experiment uses exact Three.js 0.186.1 from the root lockfile. Its stock `examples/jsm/renderers/SVGRenderer.js` was inspected and is bundled unchanged as a comparison, alongside Three.js core. Complete Three.js MIT text from the installed package is included in both generated prototype HTML files. The custom IllustrationSVGRenderer, scene helpers and depth overlay are new code; Three.js internals are not patched. The original M1 package excluded Three.js; that boundary was superseded by the subsequent user-authorized migration.

Version 0.2 packages Three.js 0.186.1 as its own runtime dependency, with `licenses/three-MIT.txt` from the installed package and the complete notice in generated browser bundles. `kit/three/renderer.mjs` develops the experiment's overlap/ray ordering approach into a DOM-independent serializer and retained browser view. Its primitive helpers use Three.js ExtrudeGeometry, CylinderGeometry and TubeGeometry, including matching sampled rings for the SVG surface data. No Three.js internals, upstream turn engine or raw WebGL shaders were copied into the production package. The experimental depth overlay and stock comparison remain outside it.

The new canonical dial keeps the upstream-inspired instrument composition but replaces its former projected-path assembly with `examples/dial-indicator/scene.mjs`. Model units and mapping are unchanged. The old view is retained as `tests/fixtures/m1-baseline/dial-rest.svg` and in the local migration-baseline evidence. The valve, cabinet and arm scenes and model functions are newly authored. Their packaged recipe templates are generated by `scripts/sync-templates.mjs` from the canonical examples; changes are maintained in the examples rather than edited in two places.

Revision 2 (0.3.0) adds independently authored construction, material, motion, audit, effects, React and print modules. The upstream `lathe`, `tube`, audit, turn-audit, line, React, print and corresponding example sources were used as capability references. The implementation uses native Three geometry/transforms with our metadata, independent geometric/ray checks and new parameterized GLSL recipes; it does not transplant the turn engine or raw upstream WebGL runtime. Adaptive meridian refinement, curve frame/ring metadata, tone clipping, interleaved passes and depth-limited volume integration are maintained here. New code licensing remains the owner's decision.

Independent R09 migration sources contain formulas explicitly extracted from the supplied upstream examples, with the original MIT notice and source hashes preserved in their source bundle. They live in evaluation artifacts rather than silently becoming toolkit code. The trial documents every manual model/control mapping and incomplete feature. The original and corrected frozen package manifests are retained alongside the evaluations; correcting a package does not rewrite earlier findings.

In 0.6.1, minimal unchanged R09 and gap-trial inputs were copied into `tests/fixtures/regressions/` so current maintainer regressions can run from a fresh checkout. Its `provenance.json` records original relative locations and exact file hashes. R09 MIT notices accompany those test fixtures. These test-only extracted model/scene inputs are excluded from the skill package and do not reintroduce the removed Anatomy renderer. Original evaluation records remain unchanged and are validated separately through `evals/historical-manifest.json`.

0.7.0 adds `licenses/napi-rs-wasm-runtime-MIT.txt`, copied unchanged from the [napi-rs repository](https://github.com/napi-rs/napi-rs/blob/main/LICENSE), because `@napi-rs/wasm-runtime` ships no license file. `@rolldown/binding-wasm32-wasi` likewise ships none, so the runtime carries the MIT notice from the `rolldown` package it belongs to. `scripts/build-runtime.mjs` now fails if any shipped dependency has no notice.
