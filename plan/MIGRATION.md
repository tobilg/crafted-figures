# Three.js replacement candidate — intermediate milestone M3

The user approved this subsequent milestone after M1/M2, with "yes, do that". That superseded the original PRD's production-migration boundary for the work below. [PRD revision 2](PRD.md) now specifies the full replacement scope and incorporates this work as intermediate milestone M3. Preserve the original baseline/prototype evidence and M01–M05 IDs. The 33 ms diagnostic budget remains deferred.

Deliver a packaged Three.js pipeline with the full dial, then broaden it through a valve/pipe example, a cutaway cabinet/wiring example, and an articulated mechanism. Preserve the public configuration, pure model and figure render contract, selected poses, accessible immediate/reduced-motion controls, standalone vector/HTML exports, determinism, independent installation and notices. Browser mount may receive additional toolkit/tokens arguments without breaking existing clients.

Three.js owns scene hierarchy, transforms, geometry and camera. Our finite SVG adapter owns semantic shading, outlines and checked painter ordering. Add primitives for concrete examples; diagnose unsupported constructions. No general mesh engine, arbitrary camera orbit, external publication or global installation is authorized.

Acceptance:

- M01: Full dial uses the packaged Three.js pipeline; prior A01–A13 outcomes pass with reviewed visual differences.
- M02: Runtime/static renderer share scene geometry and camera; visible primitive metadata agrees with actual mesh geometry, ordering failures remain explicit, and static exports require no DOM/WebGL.
- M03: Valve/pipes, cabinet/wiring and articulated examples exercise the extended vocabulary, both themes, named states and truthful models.
- M04: Packaged starters and focused craft recipes enable authoring outside this repository; isolated installation verifies actual Three.js dependency resolution and interactive as well as static exports.
- M05: Fresh independent agents create unfamiliar explainers using a frozen package; report actual artifacts, review results and limitations.

This milestone's candidate readiness is judged from these figures and authoring trials, not inferred from the successful prototype or claimed as complete Anatomy feature parity. PDF and React remain outside this specific milestone but are required later by the full PRD. Upstream gallery publication is intentionally replaced by portable local sharing; remote publication remains an optional separate workflow.

After M01–M05, continue through PRD milestones M4–M7: geometry/material/camera/audit parity, full motion and hybrid effects, typed React/Next.js integration, printing, craft/templates, source migration, capacity evidence and replacement release gates. Do not use the narrower scope of this intermediate note to exclude those capabilities from the product or to declare the full replacement finished.
