# Crafted Figures

Build the explanation around a truthful model and a recognizable object that someone wants to look at. Use this folder as the toolkit; it is self-contained.

With Node 22.13+ or Node 24+, run `node scripts/figures.mjs build ...` directly. Install the built `crafted-figures-<version>.zip` artifact. Its generated `runtime/` contains Vite 8 and the required libraries; do not run npm installation for standalone authoring. A raw source checkout requires the repository build first (`npm ci`, `npm --prefix skill/crafted-figures ci`, then `npm run package:skill` at its root). Browser checks/PDF use the pinned Chromium if installed, otherwise Chrome, Chromium or Edge already on the machine; see [verification.md](references/verification.md). React applications retain their own framework dependencies.

1. Work out how the object really works, then identify the quantity or relationship to explain, its units and bounds. Read [craft.md](references/craft.md) before any geometry: it covers both the truth of the object and what makes a figure worth looking at. Choose geometry that makes the relationship visible. Keep explicit constraints, medium and requested scope.
2. Read [authoring.md](references/authoring.md) for the small figure/model/client contract and starter. Build a working static pose before adding interactions. New figures use the packaged Three.js scene and SVG adapter. Use [geometry.md](references/geometry.md) when constructing parts; diagnose unsupported overlaps instead of hiding them.
3. Choose the look. Use `"preset": "illustrated"` for everyday objects and general readers, and `technical` or `editorial` for instruments and drawing-like figures. Read [configuration.md](references/configuration.md) for appearance changes. Translate user preferences into config or CLI flags; keep the model independent. Presets, detail and framing are choices, not mandatory ornament or part counts.
4. Add only necessary controls. Drive geometry and readout from the same displayed state. Keep pointer and keyboard behavior equivalent, reduced/disabled motion immediate, and idle tours off unless requested. Return cleanup from mount. A figure with its own states, such as a toaster's stages, can keep them in a custom client and call `kit.illustration.publishState(root, state, reading)` after each change. Use [motion.md](references/motion.md) for reversible sequences and changing shapes, and [effects.md](references/effects.md) for bounded hybrid layers.
5. Run [verification.md](references/verification.md): model checks, standalone build/check, `audit` for contacts and clearances (`check` does not look for parts cutting into each other), `drive` for the states a reader reaches, desktop/mobile views and 4× crops at contacts/overlaps. Inspect screenshots before accepting them, for appeal as well as correctness. Record any blocked check explicitly.
6. For framework embedding, read [react.md](references/react.md). For print/PDF or portable source bundles, read [printing.md](references/printing.md). Deliver source, requested standalone files and evidence. HTML/SVG viewers need no network or npm install. Do not publish, install globally, or add account integrations as a side effect.

Keep text escaped and configuration validated. Author modules are trusted executable code. The packaged Three.js pipeline supports the documented illustrated primitives, fixed authoring cameras and model-driven motion. Version 2 adds declared camera views, material overrides and bounded hybrid recipes. It does not support arbitrary meshes, unrestricted camera controls or automatic shader-to-SVG conversion. Qualify claims against the actual figure envelope and executed verification. A successful build alone does not show that an advanced feature works.
